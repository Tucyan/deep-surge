## 2026-10-02｜玩法探索

### 世界观与比赛主题

确定游戏名称为 **Deep Surge**。世界处于陆地被海洋淹没后的“水世代”，海洋是不断涌出遗迹、生物与资源的神秘活体系统，每局 Roguelike Run 对应一次涌潮周期。

围绕比赛主题“涌现”，将体验分为三个相互连接的部分：海洋涌出物资、同一物资转化为不同用途，以及卡牌、工具、设施与环境组合产生新的结果。例如漂流木可以修船，也可以与布条、点火器组合制作火把；暴雨遇到集雨器时，除了直接补给，还能推进设施生产。

战斗参考《邪恶冥刻》的航道位置、可见意图和部署后交战表达，不将牺牲或献祭作为核心系统。设计重点转向物资分配与规则联动，随机抽取负责改变处境，不能单独替代“涌现”玩法。

### 航行方案探索与收敛

最初分别讨论了两种方案：每轮随机二选一的 A，以及带暗流、漩涡、视野和载具的网格 B。曾制作一层 HTML B 方案 POC，之后按要求连同实现计划移入本地 `.bin` 并附说明；该版本不再推进，其验证记录也不代表当前规则已经实现。

随后确定采用 **A，每轮随机出现 2～3 个候选节点，选择一个前往**。未选候选在提交航行后失效，下一轮重新生成；没有网格、地图视野、寻路或返回旧节点。整体玩法文档已经移除 B 章节、两方案比较和网格专属规则，只保留 A。

航行工具据此调整：逆流桨用于重掷本轮候选，折叠锚用于抵消所选节点的一次环境船体损伤，听潮筒用于查看当前候选的额外详情。漩涡和冷雾作为事件节点表达，不产生空间位移或视野范围。

## 2026-10-02｜首版规则初步确定

将可玩切片收缩到一个海层：航行、普通怪物战斗、确定工具合成、生存结算和轮末弃牌。完整五层 Boss、商店、藏品、策略、自然物经济及随机高级合成保留为后续扩展，不加入首版。

| 系统 | 初步确定的规则 |
|---|---|
| 航行 | 每轮随机生成 2～3 个候选，至少一个非战斗选项；提交一次航行消耗一次额度 |
| 行动力 | 航行准备和战斗回合分别刷新 AP，默认各 3；刷新是设值，战后不重复准备或补给 |
| 卡牌费用 | 按卡牌用途分别计费，0～3 只是示例，不是永久上限；纯原料和工具条件不伪装成 0 费出牌 |
| 手牌 | 初始上限 10，轮内允许超限并继续行动；弃牌只在轮末开放，整理后才能进入下一轮 |
| 生存 | 跟踪木筏耐久、角色生命、饱食、水分和 SAN；战斗回合不重复推进航行生存消耗 |
| 木筏 | 首版四个防卫位、两个后勤位；部署移出手牌，设备与船体战损持续保留 |
| 普通战斗 | 四航道、可见意图、固定来敌；处理完全部怪物才胜利，空航道不能绕过怪物获得胜利 |
| 材料弱点 | 部分怪物只接受所需材料类型卡牌的进攻效果，不新增攻击属性；自动攻击同样检查来源类型 |
| 工具合成 | 消耗配方 AP 与原料，工具默认保留，产物进入手牌；随后使用或安装另付费用 |
| 物资生命周期 | 实体消耗后不进入循环牌库；临时战术物资战后清除，不能制造永久物资 |
| 随机与信息 | 已知风险和怪物弱点直接显示；打开界面、预览和取消不会重掷，主动重掷不刷新 AP 或补给 |

形成首版内容表：**24 张物资卡、8 条确定配方、3 种普通怪物、12 类节点**。首版物资表不包含独立的临时战术补给。起手为手工工具、点火器、漂流木、布条、干粮、淡水、鱼叉，共七张；第一轮补给后达到十张。

弱点判定由原先拟议的独立攻击属性，修正为现有材料类型匹配。胶膜水母仅接受热源类型，绝壳蟹仅接受能量类型；熟鱼等没有进攻用途的牌不能因标签匹配而自动攻击。首次限定遭遇前需提供应对机会，避免纯随机死局。

形成并整理两份规则依据：

- [整体玩法设计](../Deep-Surge-整体玩法设计-v0.1.md)：玩法循环、AP、生存、战斗、合成和后续扩展边界。
- [首版卡牌与节点设计](../Deep-Surge-首版卡牌与节点设计.md)：首版卡牌、配方、怪物、节点和候选生成规则；具体内容优先采用此表。

规则与数值均尚未经过正式游戏实测，当前确定的是实现与验证的起点，不是最终平衡结果。

### 22:39:04｜对齐 Unity/C# 技术方向

提交：`e5e068118aad2a6ab2b779476db8c47193251f2c`
标题：`docs: align architecture and contracts with Unity C# stack`

确定技术栈为 **Unity 6000.3.19f1 + C# + UI Toolkit**，目标为 Windows 本地单机。开发方向由早期基于 HTML 原型接入规则，调整为直接制作 Unity 最小可玩 Demo；`water-era` 仅作为视觉与交互参考，不继续开发 HTML 规则 Demo。

同步调整 README、协作约定、两份规则文档和三份程序契约，将契约对齐为普通 C# 类型与 Unity 适配边界。正式工程目录暂定 `deep-surge-unity/`，补充缓存、日志、IDE 文件和构建产物忽略规则，约定未来跟踪 Assets（含 `.meta`）、Packages 与 ProjectSettings。

| 程序设计项 | 初步契约 |
|---|---|
| 规则核心 | 纯 C#，通过 asmdef 的 No Engine References 隔离，不依赖 UnityEngine、帧时间或场景对象 |
| 应用入口 | GameSession 接收命令，负责阶段、费用、事务与状态版本；Unity 接收只读视图和事件 |
| 内容编辑 | ScriptableObject 仅用于编辑，启动时转成纯 C# 内容定义，局内不修改资产 |
| 实体追踪 | 唯一实例 ID 跟踪材料消耗、鲜度、部署、临时生命周期及持久战损 |
| 随机 | 显式种子、固定算法与可恢复随机状态；预览和拒绝命令不推进随机流 |
| 存档 | 使用显式 JSON DTO，记录 schema、内容与随机算法版本，不序列化场景引用 |
| 验证路线 | 固定种子 EditMode 测试验证规则；PlayMode 验证 UI、场景集成与恢复 |

该阶段 Unity 程序契约现保留于：[架构与状态流程](design/unity/architecture.md)、[抽象层接口](design/unity/interfaces.md)、[数据结构与内容契约](design/unity/data-model.md)。其中参数试测、临时实体时限和部分事务细节属于程序设计决策，未将它们冒充已经实测的原玩法规则。
