# 第一层 Three.js Demo v1 实现与验证

日期：2026-10-03。代码仓库 `water-era/`，启动页 `dist/index.html`。已实现五次航行的可玩循环和简单开始界面，不包含 Boss。保留现有海面/木筏/远景布局，卡牌、节点及普通怪物使用用户素材；设施使用程序化 3D 模型。

## 已实现

24 张 C 类卡、8 个确定配方、12 个节点、3 种普通怪物；七张起手、一次补给、工具保留、合成与使用分别收费、轮末十张上限；每轮 2–3 候选与补给保底、航行干预；四航道战斗、材料检查、束缚/浸湿、意图拦截、设备结构/残骸、基础划杆/防护/撤退与第七回合起深潮；一次航行饥渴结算、外围格随机受损、两个后续航行轮老化、修补/停用/脱落、生产与鲜鱼腐坏；通关、失败、重开、规则说明、日志和画面设置。

C07 灭火用途因首版没有燃烧施加而明确禁用，不新增燃烧规则；C23 随提交航行消耗。扩展板只在资产工坊展示，首版没有扩建费用，不加入玩法扩建。

## 程序与契约

`game/content/catalog.js` 是纯数据；`game/rules/` 分成 cards/battle/voyage/common；`game/session.js` 提供 createSession / restoreSession、dispatch({expectedRevision,command})、preview、getSnapshot/getView、exportSave。事务在状态副本执行，通过不变量后提交；失败或预览不改变 AP、物资、版本与随机流。规则模块不依赖 DOM/Three.js/帧或浏览器存储。

状态为 JSON 数据，记录 schemaVersion=1、contentVersion=first-layer-v1、randomAlgorithm=lcg32-v1 和五个随机流；设备、卡、敌人、储存产物使用唯一 ID。getView 隐去随机状态和未揭示候选细节，显示敌人意图/材料/可工作状态。app 通过命令接入，scene.syncDemo 接收只读视图；不再使用 window.gameState。

[接口](../design/interfaces.md)/[数据模型](../design/data-model.md)/[架构](../design/architecture.md) 仍是完整目标契约，当前实现有明确差异：preview 返回允许/费用/原因，尚无完整 EffectPreview；dispatch 的 events 仅为 Log 通知，尚无全套类型化领域事件；内容直接导入，暂未提供目录注入端口；奖励在节点命令内处理，没有独立 ClaimReward/DeclineReward；SwapDefense 使用单位 ID 和目标槽。未来拆分需兼容当前玩法与随机恢复，不能声称完整契约已实现。

## 程序试测决策

以下为 Demo 默认值和实现选择，不能视为玩家讨论确认或已经平衡：

- 初始筏面 4×3=12 格，沿用场景布局；四防卫槽在前排，两后勤槽绑定中排角格。格子数量不等同于整船耐久。
- C20/C21 结构暂设 4；其生产周期和容量使用首版规则。其他设备结构使用首版表。
- 合格候选池等概率，不引入权重；第一次补给候选优先提供 N04 工具箱，后续随机。能量遭遇需曾同时拥有绝缘钳/蓄电碎片/废铁；初始起手已提供热源制作机会。
- 战术补给稳定选项 T01 为临时盾；另一选项目前为 T02 临时材料攻击（2 伤害），作为最小试测池，无高级随机合成。tactical 随机流保留但当前单项备选池不抽取。
- 紧急防护持续到下一次普通生命伤害，跨过仅处罚筏格的回合；不抵挡 SAN、筏格、深潮或精神崩溃。每战斗回合最多操作一次，已有防护时不能叠加。
- 轮末腐坏移除到期鲜鱼；制作自动挑选符合条件的实体，也支持明确原料实例 ID；轮内超限允许，超限最后奖励仍先弃牌再通关。

## 数值平衡试测优化 v4

2026-10-03，经多轮实机模拟与持续游玩实测（50 局基准数据比对），针对首层 5 轮航行切片优化了部分失衡数值，标注为改版试测数值，不改变底层阶段契约：

1. **后勤设施生产周期适配**：`C20` 捕捞网与 `C21` 集雨器生产阈值由原版的 3 轮 / 4 轮调整为 **2 航行轮**。在首层仅 5 次航行的规模下，原版 4 轮集雨器在中期部署往往导致直至通关 0 产出，收益彻底沉没；调为 2 轮后，第 2～3 轮部署的设施能在第 4～5 轮获得 1～2 次产出，暴雨（+2 进度）亦能产生立竿见影的联动。
2. **涌泉池卡牌权重优化**：原版漂流木（C01 权重 18）与饮食用料（C07/C08 各 16）合计占比过半，导致玩家手牌频繁被漂木挤占，每局平均强制弃牌高达近 20 张。试测调整权重为：`C01: 14, C02: 12, C03: 10, C04: 12, C05: 8, C06: 8, C07: 12, C08: 12, C09: 6, C17: 4, C18: 2`（总计 100）。增加废铁、能量碎片、绳索与进攻防卫物资的抽取几率，激活更多合成与应对可能。
3. **事件节点投入产出比修正**：
   - `N10` 沉浮观测站：休整选项 SAN 恢复由 +8 提升至 **+15**，提升面对精神攻击敌人后的休整性价比。
   - `N12` 冷雾漂流物：驱雾消耗 1 火把 + 1 AP，奖励调整为获得 **布条 + 干粮 + 淡水**（原为布条 + 干粮），修正了原本“净消耗 2 AP + 1 漂木换 1 干粮”的负收益问题，使其成为值得用火把探索的高收益事件。

### 记录待后续处理的游玩体验问题（非紧急暂不修复）

- **战斗弱点死锁与克制缺失**：面对仅弱热源的 M02 胶膜水母或仅弱能量的 M03 绝壳蟹时，若玩家手牌无克制卡且无原料合成，战术补给池仅提供无属性的 T01 盾与 T02 碎木，基础长杆驱离亦受限于材料限制，导致无法造成任何伤害，只能硬抗至第 7 回合深潮暴毙或花费 4 HP 撤退；建议后续战术补给池动态提供克制临时牌，或增加保底刮痧机制。
- **临时盾残骸堵塞防卫槽**：T01 稳妥漂木盾被打爆后留有 0 结构残骸，阻碍次轮在该槽位部署新防卫，需要额外花费 1 AP 拆除或移动；后续可考虑临时盾战后自毁或支持覆盖部署。
- **工具箱（N04）候选霸屏**：由于保底逻辑与未领取状态判断，N04 在部分种子中频繁刷出（单局出现 3～4 次），挤占了其他环境和事件节点；后续可引入领取后移出池或递减权重机制。
